🎯 Comment utiliser cette banque

Cette banque couvre uniquement les 4 chapitres de la Séance 3 : présentation de React, écosystème (npm, ES6, Babel, bundlers), architecture d'une application React, et structure d'un premier projet create-react-app. Le cours ne détaille pas encore l'écriture de composants JSX ni les Hooks en profondeur (ils ne sont que cités p.8) — cette banque reste donc volontairement au niveau conceptuel/lecture de code, sans dériver vers des notions non enseignées.

Pour chaque exercice : lis l'énoncé, essaie seule, ouvre l'indice si tu bloques, puis seulement ensuite le corrigé et la solution attendue. Coche le statut quand c'est fait.

NIVEAU 1

Fondamentaux

📌 À savoir avant de commencer
  • React est une bibliothèque JavaScript (Facebook) pour créer des composants réutilisables.
  • Le DOM virtuel est une copie interne du DOM que React utilise pour limiter les mises à jour réelles.
  • npm gère les dépendances et lance des scripts (install, start, test, run dev).
  • Babel transpile l'ES6 vers l'ES5 ; Webpack/Browserify fusionnent les fichiers (bundling).
  • Un projet create-react-app a un dossier public/ et un dossier src/.

EXERCICE 1 — React, jQuery et le DOM virtuel

[Exercice d'entraînement]

📁 ex01_react_jquery_dom_virtuel

📄 Fichier principal : ex01.md

⭐ Niveau 1

Notions mobilisées : définition de React, DOM virtuel, comparaison avec jQuery

🎯 Objectif : Vérifier la compréhension de la définition de React et du principe du DOM virtuel.

📝 ÉNONCÉ

Réponds aux questions suivantes en une phrase chacune :

  1. Qu'est-ce que React et par qui a-t-il été créé ?
  2. Quelle est la différence entre la manière dont jQuery et React manipulent le DOM ?
  3. Pourquoi cette différence rend-elle React plus performant ?

🧑‍💻 À TOI DE JOUER

  • Rédiger une réponse courte pour chaque question.
  • Éviter de recopier mot pour mot le cours : reformule avec tes propres mots.

📊 STATUT :

💡 Indice
Pense au mot « copie » : React ne touche pas directement le HTML affiché, il compare une version en mémoire avant d'agir.
🧠 Astuce
Réflexe examen : si la question porte sur « pourquoi React est rapide », la réponse tourne presque toujours autour du DOM virtuel et de la synchronisation ciblée.
✅ Corrigé

1. Analyse : la question teste une définition (React) et un mécanisme (DOM virtuel).

2. Méthode : distinguer « manipulation directe » (jQuery) vs « copie interne + synchronisation » (React).

3. Implémentation : rédiger trois réponses courtes et précises.

4. Résultat attendu : voir solution ci-dessous.

5. Explication : la manipulation directe du DOM réel est coûteuse car le navigateur doit recalculer l'affichage à chaque changement ; travailler sur une copie permet de grouper les changements avant de toucher le DOM réel.

💻 Solution attendue

1. React est une bibliothèque JavaScript développée par Facebook, utilisée pour créer des composants d'affichage réutilisables.

2. jQuery manipule directement les éléments du DOM réel, alors que React travaille sur une copie interne appelée le DOM virtuel.

3. Parce que React ne met à jour l'affichage réel que lorsque c'est nécessaire, ce qui évite des manipulations directes coûteuses et améliore les performances.

🔎 Explication de la solution
On distingue bien « bibliothèque » (React n'est pas un framework complet) de « framework ». Le mot-clé à retenir pour l'examen est « synchronisation ciblée » : React ne réécrit pas tout le DOM, seulement ce qui a changé.

📊 STATUT :

EXERCICE 12 — Analyse critique de App.js

[Exercice d'entraînement]

📁 ex12_analyse_critique_app_js

📄 Fichier principal : ex12.js

⭐⭐⭐⭐ Niveau 4

Notions mobilisées : composant fonction, JSX, export default

🎯 Objectif : Lire un composant réel et en identifier tous les éléments constitutifs.

📝 ÉNONCÉ

import logo from './logo.svg';
import './App.css';

function App() {
  return (
    <div className="App">
      <header className="App-header">
        <img src={logo} className="App-logo" alt="logo" />
        <p>Edit <code>src/App.js</code> and save to reload.</p>
      </header>
    </div>
  );
}

export default App;

🧑‍💻 À TOI DE JOUER

  • Identifier : le nom du composant, ce qu'il retourne, et ce que fait la dernière ligne.
  • Expliquer pourquoi className est utilisé à la place de class.
  • Dire ce qui se produirait si on oubliait export default App;.

📊 STATUT :

💡 Indice
class est un mot réservé en JavaScript (pour les classes ES6) — le cours précise que le JSX se transforme en appels JavaScript.
💻 Solution attendue

Le composant s'appelle App, c'est une fonction qui retourne une expression JSX définissant ce que le navigateur affichera.

export default App; rend le composant disponible pour les autres modules (notamment index.js qui l'importe).

className est utilisé car class est un mot réservé du langage JavaScript (pour les classes ES6) ; React utilise donc className pour éviter le conflit.

Sans export default App;, index.js ne pourrait pas importer le composant App, et l'application ne pourrait pas s'afficher (erreur d'import).

MODE EXAMEN

Mini-sujet complet

SUJET — Reprise en main d'un projet React existant

⏱️ Durée indicative : 25 min · ⭐⭐⭐⭐⭐ · 📊 Barème : 20 pts

ÉNONCÉ

On te confie un projet React existant, généré avec create-react-app, récupéré depuis un dépôt GitHub. Le fichier src/App.js actuel est le suivant :

import './App.css';

function App() {
  return (
    <div className="App">
      <h1>Bienvenue</h1>
    </div>
  );
}

export default App;

Ce composant provoque actuellement une erreur au démarrage.

TRAVAIL DEMANDÉ

  1. (4 pts) Liste, dans l'ordre, les commandes à exécuter dans un terminal pour récupérer ce projet depuis GitHub et le démarrer en local.
  2. (4 pts) Identifie précisément l'erreur présente dans le code de App.js et explique sa cause technique (en te basant sur le fonctionnement du JSX).
  3. (4 pts) Explique le rôle exact de index.js dans le fait que ce composant App s'affiche réellement dans le navigateur.
  4. (4 pts) Un collègue propose d'ajouter Webpack seul (sans Babel) pour accélérer le build. Explique pourquoi cette proposition est incorrecte.
  5. (4 pts) Le projet doit prochainement gérer plusieurs pages (accueil, contact, à propos) et un état utilisateur partagé entre plusieurs composants. Cite les deux familles de composants tiers à envisager, avec un exemple pour chacune.
🧠 Conseil de gestion du temps
Compte environ 5 min par question. Traite la question 2 (l'erreur) en premier : c'est la plus concrète et elle rassure pour la suite. Garde 2 minutes en fin de sujet pour relire tes réponses aux questions 4 et 5, souvent bâclées par manque de temps.
✅ Corrigé complet

1. git clone [lien-du-dépôt] → cd nom-du-projet → npm install → npm start.

2. Il manque import React from 'react'; en haut du fichier. Cause : tout composant React doit importer React, car le JSX écrit dans le return est transformé en React.createElement(), une méthode fournie par ce module. Sans cet import, la transformation échoue et une erreur est levée.

3. index.js importe le composant App, crée une racine React sur la div #root de public/index.html via ReactDOM.createRoot(...), puis appelle .render(<App />) pour afficher ce composant dans cette racine. Sans ce fichier, App ne serait jamais monté dans le DOM réel du navigateur.

4. Webpack seul ne sait fusionner que des fichiers déjà compréhensibles par le navigateur : il ne transforme ni le JSX, ni la syntaxe ES2015. Sans Babel (presets es2015 et react), le code du projet ne sera pas transpilé et l'application ne fonctionnera pas dans la majorité des navigateurs.

5. Gestion des routes → React Router (pour naviguer entre accueil/contact/à propos sans recharger la page) ; Gestion avancée de l'état → Redux ou MobX (pour partager l'état utilisateur entre plusieurs composants éloignés dans l'arbre).
